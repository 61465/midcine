## Phase 1 — 4 Parallel Tracks (5-7 days each, in parallel)

### Track A: Viewer UX overhaul
**Doctor's complaint #1**: "unorganized display"

**Diagnosis** (needs verification from current viewer code):
- Toolbar likely cluttered / non-standard
- No preset hangs (Ax + Sag + Cor MPR grid)
- Window/level presets missing or hidden
- No keyboard shortcuts (`W` window, `L` level, `↑↓` slice, `←→` series)

**Fixes**:
- **Layout**: 3-viewport MPR grid by default for cross-sectional (CT/MRI). 1x1 for X-ray.
- **Preset hangs** (auto-select by modality + body part):
  - CT Brain → Ax + Sag + Cor
  - CT Chest → Ax + Cor lung window + Cor mediastinal
  - MRI Knee → Sag T2 + Cor T1 + Ax PD
  - MRI Brain → Ax T1 + Ax T2 + Ax FLAIR + DWI
  - X-ray → 1 viewport, 100% zoom
- **W/L presets** dropdown: Bone 400/1500, Lung -600/1500, Brain 40/80, Soft 40/400, Liver 60/150, Custom
- **Toolbar**: 8 primary tools (Scroll, Pan, Zoom, W/L, Ruler, Angle, Annotate, Reset). Everything else moved to a "Tools" menu.
- **Keyboard shortcuts** documented in a `?` help overlay
- **Cornerstone3D 2.0** APIs (already installed per delivery report)

**Owner**: `frontend_dev` NEXUS agent + Claude review

### Track B: Full-series display + navigation
**Doctor's complaint #2**: "only shows one image from the series"

**Diagnosis**:
- Viewer shows first slice + doesn't wire scroll to `imageIds` array
- OR: series is loaded but no thumbnail rail to jump between series
- OR: MRI multi-series (T1/T2/FLAIR) not detected as separate stacks

**Fixes**:
- **Thumbnail rail** on left side showing every series in the study (with modality tag)
- **Slice scroll**: mouse wheel = advance slices, `↑↓` arrows, drag scrollbar
- **Cine playback**: `Space` to play/pause, adjustable FPS
- **Series switcher** dropdown at top of each viewport
- **Progress**: slice X of Y indicator
- **Preloading**: fetch full series in background, show progress bar (matters for slow net)

**Owner**: `architect` NEXUS agent + verify Cornerstone3D 2.0 has `StackViewport.setStack(imageIds)` implemented correctly

### Track C: AI accuracy hardening (grounded, template-constrained)
**Doctor's complaint #3**: "many AI errors"

**Diagnosis** (from DELIVERY_REPORT + memory):
- Vision LLM (Groq scout) can hallucinate anatomy or findings
- No slice-citation requirement → AI says "there is a mass" without pointing where
- No structured constraint → free-text reports have inconsistent format
- No second-opinion → single AI voice, no cross-check

**Fixes** (offline-first per Track D):
1. **Grounded output**: system prompt requires every finding to cite slice number(s). If model omits, reject + retry.
2. **Structured templates** (Findings/Impression sections, one line per finding, ACR reporting format)
3. **Confidence filter**: hide findings with <70% confidence in the main report, expose in a "Weak signals" section
4. **Devil's advocate agent**: after first AI report, a second agent (offline: local Ollama, or online: NEXUS guardian) reviews the report against the images and flags contradictions
5. **CV model integration** (separate model per anatomy):
   - **Chest X-ray**: TorchXRayVision (14-class DenseNet, ONNX, ~30MB) — runs locally
   - **CT brain**: MONAI Brain Tumor / Stroke segmentation (ONNX)
   - **Knee MRI**: RSNA baseline (from Kaggle competition — 12-class multi-label)
   - **Chest CT**: TotalSegmentator (heavy, opt-in premium tier)
6. **Report caching**: same study + same model = same report (deterministic seed) — reduces user confusion

**Owner**: `algorithm_expert` + `model_optimizer` NEXUS agents

### Track D: Offline-first architecture
**New constraint**: "يحتاج نت قوي للغاية وهذا صعب في مصر"

**Diagnosis**:
- Current AI pipeline calls Groq/Bynara cloud APIs → 2s minimum + fails on slow net
- Voice dictation uses cloud STT (Web Speech API) — needs net
- Bundle size may load slow (Next.js chunks + Cornerstone3D)

**Fixes**:
1. **Primary AI = local Ollama**:
   - Vision: `qwen2.5-vl:7b` or `llava:13b` (bundled in `docker-compose.premium.yml`)
   - Text: `qwen2.5:7b` (already in current setup)
2. **Cloud AI = optional enhancement** — button says "Enhance with cloud AI (requires internet)" — disabled if not reachable
3. **Model bundles**: TorchXRayVision + MONAI models pre-downloaded to `E:\luffy-data\models\` (portable USB)
4. **Voice STT**: Vosk (offline) as primary, Web Speech as fallback if online
5. **Bundle size**: Verify `apps/web` bundle < 5MB gzipped. Split Cornerstone3D per-modality (don't load Volume renderer for X-ray)
6. **Network status indicator** in top bar: "🟢 Cloud AI available" / "🟡 Slow — using local" / "🔴 Offline mode"
7. **Queue+retry**: any cloud call that times out queues for retry when net returns
8. **PWA offline mode**: service worker caches app shell + last opened studies

**Owner**: `devops_master` NEXUS agent + Claude verifies each cloud call site
