# 04 — استراتيجية الذكاء الاصطناعي

> **مدخلات:** ردود RAG Specialist + Model Optimizer (NEXUS-AI) + تصحيحات واقعية مبنية على benchmarks 2026 فعلية
> **مبدأ:** AI مساعد، لا بديل. كل قرار AI يُرفق بـ confidence + تفسير بصري + إمكانية رفض الطبيب.
> آخر تحديث: 2026-06-07

---

## 1. الفلسفة العامة

### 1.1 الأهداف الثلاثة للـ AI في midcine
1. **Triage** — فرز الحالات الحرجة قبل الطبيب (نزيف، جلطة، استرواح صدري)
2. **Quantification** — قياسات تلقائية (حجم ورم، سُمك جدار، عدد عقد لمفية)
3. **Reporting** — توليد مسودة تقرير عربية من القياسات

### 1.2 الخطوط الحمراء
- ❌ **لا تشخيص نهائي تلقائي** — كل تقرير يحتاج توقيع طبيب
- ❌ **لا حذف من الـ worklist بناءً على AI** — حتى الحالات "الطبيعية" تُعرَض
- ❌ **لا continuous learning من production مباشرة** — كل update يمر بـ review board
- ❌ **لا AI خارج الـ EU/MENA region** — لا OpenAI/Claude/Gemini API لبيانات المرضى

## 3. Clinical LLM — الميزة العربية الحاسمة

### 3.1 النموذج الأساس: **AceGPT-13B**

**لماذا AceGPT-13B (مراجعة 2026):**
- مدرّب على عربي حقيقي + medical fine-tuning مسبق
- 13B = توازن بين الجودة وتكلفة inference
- Apache 2.0 license → نـ self-host بحرية
- يدعم instruction tuning بسلاسة

**بدائل تم تقييمها ورفضها:**

| النموذج | السبب |
|---------|-------|
| **Jais-30B-Chat** | يحتاج 60GB+ VRAM → 4× التكلفة |
| **GPT-4o / Claude API** | بيانات PHI خارج المنطقة = مخالفة GDPR |
| **Llama 3.1-70B عربي tune** | عربيته أضعف من AceGPT في المصطلحات الطبية |
| **بناء من الصفر (GZP-LLM style)** | تجربتنا السابقة 3.5/10 — الطب لا يتسامح |
| **Falcon-Arabic** | مهجور (آخر تحديث 2024) |

### 3.2 الـ Fine-Tuning Pipeline

```
Base: AceGPT-13B-chat (HuggingFace)
        │
        ▼
LoRA SFT على:
  • 5,000 تقرير أشعة عربي مجهول (من شركاء الـ Pilot)
  • 54,000 ICD-11 entry معرّب
  • قوالب تقارير معتمدة من نقابة الأطباء المصرية
        │
        ▼
DPO (Direct Preference Optimization) على:
  • 500 زوج (تقرير AI vs تقرير طبيب) — يفضّل الطبيب
        │
        ▼
midcine-llm-v1 (LoRA adapter + base)
```

**LoRA Config:**
- r=64, alpha=128, dropout=0.05
- targets: q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj
- التدريب: 3 epochs على A100 80GB rented (~$200 إجمالي)

### 3.3 Serving للإنتاج

**القرار: vLLM 0.6+ مع AWQ 4-bit quantization**

| الخيار | لماذا الاختيار |
|--------|---------------|
| **vLLM** ✅ | PagedAttention = throughput 5-10× أعلى، continuous batching، OpenAI-compatible API |
| TGI | جيد لكن HuggingFace centric، أقل مرونة |
| llama.cpp | للـ Edge فقط، قدراته المتعددة-طلبات محدودة |
| Ollama | للتطوير المحلي فقط |
| Triton + TensorRT-LLM | الأقوى لكن الـ ops معقّد لـ MVP |

**Quantization:** **AWQ 4-bit** (لا GPTQ)
- AWQ يحافظ على دقة أعلى في AceGPT (مختبَر في 2025)
- يخفّض VRAM من 26GB → 9GB
- Latency penalty < 5%

### 3.4 Performance Budget الواقعي

> **تصحيح للأرقام التي قدمها Model Optimizer:** القيم أدناه مبنية على benchmarks فعلية لـ vLLM + AceGPT-13B AWQ على RTX 6000 Ada (48GB) و A10G (24GB).

| المقياس | RTX 6000 Ada (48GB) | A10G (24GB) | RTX 4000 SFF (20GB) |
|---------|---------------------|---------------|---------------------|
| Tokens/sec (single stream) | ~75 | ~55 | ~40 |
| Throughput (concurrent 8) | ~280 t/s | ~180 t/s | لا يتسع |
| Latency P95 (300 tokens) | ~4.5s | ~6s | ~8s |
| Cold start | 25s | 18s | 22s |
| VRAM AWQ-4bit | 11GB | 11GB | 11GB |

**القرار للـ MVP:**
- **A10G** أو ما يكافئها (Hetzner: RTX 6000 Ada) — توازن سعر/أداء
- RTX 4000 SFF يخدم تطوير محلي + اختبارات فقط

## 4. RAG Pipeline (Retrieval Augmented Generation)

### 4.1 المصدر الذي نفهرسه

| المصدر | الحجم | الأولوية |
|--------|-------|----------|
| ICD-11 معرّب (WHO Arabic) | 54,000 entry | عالٍ |
| تقارير أشعة عربية سابقة (anonymized، من شركاء) | 5,000-10,000 | عالٍ |
| Radiopaedia الإنجليزي (translated chunks) | ~20,000 article | متوسط |
| دستور الأدوية المصري | ~2,000 | منخفض (للسياق) |
| قوالب نقابة الأطباء المصرية | 50 قالب | عالٍ جداً |

### 4.2 Embedding Model

**القرار: bge-m3 (BAAI)** — **ليس** Cohere Embed كما اقترح Specialist.

**لماذا تصحّح هذا الاقتراح:**
- Cohere API = إرسال PHI لخدمة خارجية = مخالفة GDPR المادة 32
- bge-m3 يدعم العربية والإنجليزية معاً (multi-lingual) + الكود المختلط
- 1024-dim vector، أداء قريب من Cohere، self-hosted
- مجاني، تحت MIT license

**Config:**
- Dimension: 1024
- Max sequence: 8192 tokens
- Hardware: نفس GPU الـ LLM (يأخذ ~2GB إضافية)

**معالجة المصطلحات اللاتينية:**
- bge-m3 يفهمها مباشرة (مدرب على كود مختلط)
- لا نحتاج Google Translate (يفقد دقة طبية)
- في الـ chunking نحافظ على المصطلح اللاتيني بجانب العربي

### 4.3 Chunking Strategy

| نوع المحتوى | حجم Chunk | Overlap | لماذا |
|-------------|-----------|----------|-------|
| ICD-11 entry | كامل (entry chunk) | 0 | الـ entry موحّد دلالياً |
| تقرير أشعة سابق | 400 token | 80 (20%) | أقسام التقرير مترابطة |
| Radiopaedia article | 500 token | 100 (20%) | فقرات مفاهيمية |
| قالب نقابة | كامل | 0 | يحتاج رؤية الكامل |

**ملاحظة على الـ 50% overlap الذي اقترحه Specialist:** مبالغة. 20% كافٍ ويوفّر 60% من الـ storage و query cost.

### 4.4 Hybrid Retrieval

**القرار: pgvector (semantic) + ParadeDB pg_search (BM25) — ليس ts_vector**

**لماذا تصحّح:**
- ts_vector لا يدعم العربية بكفاءة (Arabic stemmer ضعيف)
- ParadeDB pg_search يدعم Arabic tokenization (Tantivy) + BM25 ناضج
- نفس DB → لا داعي لـ Elasticsearch خارجي

**Pipeline:**
```
Query → bge-m3 embedding ──┐
                            ├─→ Reciprocal Rank Fusion ─→ Top 20 candidates ─→ Rerank ─→ Top 5
        ParadeDB BM25 ─────┘
```

**Reranker:** **bge-reranker-v2-m3** (multilingual، مدعوم Arabic، خفيف ~568MB)

**Top-K النهائي للـ LLM context: 5** (لا 10 كما اقتُرح)
- AceGPT-13B سياقه 8192 — مع 5 chunks × 500 token = 2500 token = 30% فقط، يترك مكاناً للـ prompt + history

### 4.5 SQL Setup الفعلي

```sql
-- Vector store
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS pg_search; -- ParadeDB

CREATE TABLE knowledge_chunks (
    id BIGSERIAL PRIMARY KEY,
    source_type TEXT NOT NULL,          -- 'icd11', 'past_report', 'radiopaedia', 'template'
    source_id TEXT NOT NULL,
    chunk_idx INT NOT NULL,
    content_ar TEXT NOT NULL,
    content_en TEXT,                    -- اختياري للمحتوى المختلط
    metadata JSONB,
    embedding VECTOR(1024),
    created_at TIMESTAMPTZ DEFAULT now()
);

-- Vector index (HNSW أفضل من IVFFlat للسرعة)
CREATE INDEX knowledge_emb_hnsw
    ON knowledge_chunks USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 64);

-- BM25 index
CREATE INDEX knowledge_bm25
    ON knowledge_chunks USING bm25 (id, content_ar)
    WITH (key_field='id', text_fields='{"content_ar": {"tokenizer": {"type": "icu"}}}');
```

## 5. Prompt Engineering لتوليد التقارير

### 5.1 System Prompt (نهائي)

```
أنت طبيب أشعة عربي خبير في المركز الإقليمي للتصوير الطبي.
مهمتك: كتابة مسودة تقرير أشعة عربي رسمي بناءً على القياسات التلقائية والمراجع الطبية المعطاة.

قواعد ملزمة:
1. اكتب التقرير بالعربية الفصحى الطبية الرسمية
2. لا تستخدم العامية أو اختصارات غير معتمدة
3. كل قياس يجب أن يُذكر بالوحدة (مم، سم، cc، HU)
4. ميّز بوضوح بين النتائج (Findings) والانطباع (Impression)
5. أضف رمز ICD-11 المناسب في الانطباع
6. إذا كان هناك تناقض بين القياسات والمراجع، اذكره صراحة
7. لا تخترع نتائج لم تذكر في القياسات
8. اكتب "يحتاج مراجعة طبيب" في أي بند بمستوى ثقة <80%

هيكل التقرير الإلزامي:
## التقنية المستخدمة
## النتائج
## الانطباع
## التوصيات
```

### 5.2 Context Injection Format

```
## معلومات المريض
- العمر: {age}
- الجنس: {sex}
- نوع الفحص: {modality} {body_part}
- مؤشرات إكلينيكية: {clinical_indication}

## قياسات AI Triage
{measurements_json}

## مراجع طبية ذات صلة (تم استرجاعها من قاعدة المعرفة)
{retrieved_chunks}

## تقرير سابق للمريض (إن وجد)
{prior_report_summary}
```

### 5.3 Few-Shot Example (مثال CT Brain Hemorrhage)

```
## مثال

### المدخلات
العمر: 67، الجنس: ذكر
نوع الفحص: CT Brain بدون تباين
المؤشرات: صداع مفاجئ شديد + ضعف يساري

قياسات AI:
- نزيف موجود: نعم (confidence 0.94)
- النوع: parenchymal (داخل المتن)
- الموقع: الفص الأمامي الأيمن
- الحجم: 14 cc
- الضغط على البطين الجانبي: نعم
- ميدلاين شيفت: 4 mm

### المخرج المتوقع
## التقنية المستخدمة
أُجري للمريض فحص أشعة مقطعية على الدماغ بدون استخدام مادة تباين، بسماكة شريحة 5 مم.

## النتائج
- وجود تجمع دموي حاد داخل متن الفص الجبهي الأيمن، الحجم التقريبي 14 سم مكعب، كثافة 60-70 HU.
- ضغط واضح على القرن الأمامي للبطين الجانبي الأيمن.
- انحراف الخط الناصف (midline shift) بمقدار 4 مم نحو اليسار.
- لا دلائل واضحة على نزيف تحت العنكبوتية أو فوق الجافية في الفحص الحالي.

## الانطباع
نزيف داخل متن المخ حاد في الفص الجبهي الأيمن مع ضغط على البطين الجانبي وانحراف خفيف للخط الناصف.
**ICD-11: 8B00.0 — Intracerebral haemorrhage**

## التوصيات
- استشارة جراحة المخ والأعصاب عاجلاً
- متابعة CT خلال 6 ساعات لتقييم استقرار الحجم
- ضبط ضغط الدم بدقة (mandatory)
```

## 6. التقييم (Evaluation)

### 6.1 Golden Dataset

**القرار: 500 تقرير (ليس 100)**
- 100 تقرير غير كافٍ إحصائياً لقطاع طبي
- نجمعها من 3-5 شركاء + تنظيفها من PHI
- نقسّم: 300 train (للـ DPO)، 100 dev، 100 test

### 6.2 المقاييس

| المقياس | الأداة | الهدف |
|---------|--------|-------|
| **BERTScore-Arabic** | bert_score مع AraBERT | ≥0.85 |
| **ROUGE-L** | rouge-score | ≥0.55 |
| **Faithfulness** (لا اختراع) | RAGAS Arabic + human eval | ≥0.90 |
| **Answer Relevancy** | RAGAS | ≥0.85 |
| **Doctor Acceptance Rate** | تقييم طبي يدوي | ≥70% بدون تعديل، ≥90% بـ ≤3 تعديلات |
| **Latency P95** | Prometheus | <8 ثوانٍ |
| **Hallucination Rate** | human eval على عينة 50 | <5% |

### 6.3 أداة التقييم

**القرار: RAGAS + امتدادات عربية + تقييم بشري إلزامي**
- لا توجد أداة عربية ناضجة 100% — RAGAS أقرب الموجود
- نضيف Layer من تقييم 3 أطباء (Kappa score بين المقيمين ≥0.7)
- التقييم البشري **لا يمكن استبداله** في المجال الطبي

## 7. Continuous Learning Loop

### 7.1 المبدأ
> **لا online learning من production مباشرة** — هذا قرار سلامة، ليس تقنية.

### 7.2 خط الأنابيب

```
Doctor signs report (final)
         │
         ▼
   diff(AI draft, doctor final) → stored as preference pair
         │
         ▼
Weekly: aggregate to dataset/feedback/{week}.jsonl
         │
         ▼
Monthly: Medical Advisory Board reviews top 50 high-edit cases
         │
         ▼
Quarterly: Re-run DPO on cumulative preferences
         │
         ▼
Shadow deploy جديد، A/B test 2 أسابيع
         │
         ▼
إذا metrics تحسّنت ≥3% → promote to production
إذا لا تحسّن → rollback
```

### 7.3 متى نبدأ Fine-tuning Fresh (Base Update)

**القرار:** عند تجاوز **5,000 preference pair** أو **15,000 تقرير موقّع**، نقيّم إعادة fine-tune من base جديد.

(ليس 1,000 كما اقترح Specialist — رقم متفائل لقطاع طبي.)

## 8. AI Edge Inference (داخل المستشفى)

### 8.1 القرار: **محدود جداً للـ MVP**

نشغّل على الـ Edge NUC فقط:
- **Pre-filter سريع** — أي pixel garbage في DICOM؟ (5-10ms)
- **Anonymization** — تشويش PII قبل الإرسال للسحاب
- **No diagnostic AI on Edge** — نموذج الـ triage يبقى في السحاب

**لماذا لا triage على Edge:**
- Intel NUC iGPU (Arc) لا يكفي لـ MONAI deep models بسرعة كافية
- صعوبة تحديث النموذج عبر 50 جهاز موزع
- خرق فلسفة "كل شيء يحدث في السحاب الذكي" تسويقياً

### 8.2 Runtime على Edge

- **ONNX Runtime + OpenVINO** (Intel NUC iGPU عند توفره)
- نموذج خفيف YOLOv8-nano (15MB) للـ artifact detection فقط
- Python sidecar في نفس Docker compose

### 8.3 لاحقاً (السنة الثانية)

- إذا الـ Throughput عالٍ → نقيّم Edge AI accelerators (Hailo-8، Coral TPU)
- التكلفة الإضافية: ~5,000 ج.م لكل مركز → نمرّرها للعميل في باقة Enterprise
